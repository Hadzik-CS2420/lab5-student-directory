🎯 Overview

CT 11 resolved collisions by giving every bucket its own linked list. CT 12 did it with no lists at all, probing forward through one flat array. This lab asks you to build both yourself, from empty method bodies.

The scenario is a student directory: names are the keys and student IDs are the values, the same data you used in CT 11 and CT 12. Part 1 is a ChainingHashTable; Part 2 is a ProbingHashTable with tombstone deletion. Two files, 13 TODOs (one of them already done for you), 100 points, and you can check your own score at any time.

This is individual work, not a code-together. Every TODO names the Code-Together where the same method was built in class — CT 11 for chaining, CT 12 for probing. Go back to those files when you get stuck.

📖 Learning Objectives

By completing this assignment, you will be able to:

  • Turn a string key into a bucket index with a hash function and % capacity
  • Resolve collisions with separate chaining: a linked list of nodes in every bucket
  • Resolve collisions with linear probing: step forward through the array, wrapping around, until a slot is free
  • Delete from a probing table with a tombstone, so searches for later keys still find them
  • Track the load factor (size / capacity) and resize before it gets too high
  • Resize by rehashing every entry into a new, larger table — and explain why copying slot for slot would be wrong
  • Explain why both tables give O(1) average lookups, and what makes them degrade toward O(n)
All your work goes in src/ChainingHashTable.cpp and src/ProbingHashTable.cpp. The headers in include/, src/main.cpp and everything in tests/ are provided — do not modify them. The tests are written against that exact interface.

TODO 7 and TODO 12 are worth 14 each — more than any other. Resizing has to rehash every entry into the new table, because an entry’s bucket depends on the capacity. And a probing remove() has to leave a tombstone, not an empty slot, or every key that probed past it becomes unfindable.

Things the Tests Check That Are Easy to Miss
  • search() returns a pointer, not a value. It returns an int* to the stored ID, or nullptr when the key is not there. The tests dereference it with *
  • Inserting a key that already exists updates it. The value changes and size() does not — both tables are tested for this
  • remove() returns bool. true when a key was removed; false for a missing key or an empty table, with size() unchanged
  • Different keys should hash differently. "alice" and "bob" must not land on the same hash value, so a placeholder that returns 0 fails that test
  • Each table has its own resize point. Chaining resizes once the load factor would pass 1.0 — the 8th insert into 7 buckets. Probing resizes once it would pass 0.75 — before the 6th insert into 7 slots
  • print() labels every bucket. Each line starts with the index, as in   [0]: , and an empty bucket shows the word empty
  • A tombstone is not an empty slot. remove() marks the slot DELETED. search() keeps probing past DELETED and stops only at EMPTY; insert() may reuse a DELETED slot; resize() leaves tombstones behind
  • In the probing table, size_ counts OCCUPIED slots only — tombstones do not count
  • No test can see a leak. The destructor tests delete a table and pass as long as nothing crashes, so an empty destructor still scores. Freeing every chain node is still your job

🔧 Common Problems

CMake does not configure

  1. Confirm you are inside the Dev Container — check the bottom-left corner of VS Code
  2. Delete the build/ folder and run cmake -B build again
  3. Confirm CMakeLists.txt sits in the root of your clone

Nearly everything fails, even the search tests

  • insert() is not working yet. Almost every test inserts first, so fix TODO 4 (chaining) or TODO 10 (probing) before anything else

Inserting the same key twice makes size() go up

  • Look for the key before adding it. If it is already there, change its value and return — do not add a second entry

A probing test hangs

  • The probe loop never meets an EMPTY slot. Make sure the index wraps with % capacity_, and that the table resizes before it fills up

After a probing remove(), other keys cannot be found

  • The removed slot was set to EMPTY. Set it to DELETED — a search stops at the first EMPTY it meets, so an empty hole cuts every probe sequence that ran through it

After a resize, entries are missing

  • Every entry has to be rehashed with the new capacity — copying slot i to slot i puts them where no search will look
  • Insert into the new array, then free the old one and update capacity_. And check that size_ ends up where it started

Chaining remove() crashes, or fails on the first node in a bucket

  • When the match is the head of the chain there is no prev; point the bucket itself at current->next. Otherwise use the trailing pointer from CT 09: prev->next = current->next, then delete current

Tests fail to build

  • Google Test downloads during cmake -B build — you need internet access the first time
  • Do not modify anything in include/, tests/ or src/main.cpp
